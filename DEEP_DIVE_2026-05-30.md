### Section 1 — engine

**`src/engine/prng.ts`** — `SeededRng.int(maxExclusive)`
- Added guard `if (!(maxExclusive > 0)) return 0;` before the floor.
- Why: `int(0)` returned a technically out-of-range `0`; negative/NaN bounds

## Caveats & guidance for future agents

**Read this before continuing the audit or running training.**

1. **No node toolchain in the audit sandbox.** `npm`/`node`/`npx` are absent
   where this audit was performed, so **nothing below has been run through
   `npm run typecheck && npm test`.** Run the gate locally before trusting any
   green checkmark in this doc. If a test fails, fix and update the status.

2. **`validateMaze` "every maze passes" is unverified against `arena`/`corridors`.**
   The reachability assertion runs over the hand-designed static mazes too. Static
   analysis says they're fully connected, but if either has a walled-off pellet
   pocket, `mazes.test.ts` will fail — and that failure is a *real latent bug in
   the maze layout*, not a bad test. Investigate the maze, don't delete the test.

3. **Reachability intentionally checks only `0` (pellet) tiles, not `2`
   (ghost-house) tiles.** The authentic classic maze has isolated `2`-tile tunnel
   stubs on row 13's edges; requiring all `2`-tiles reachable would false-fail.
   The true winnability invariant is "all pellet tiles reachable." Don't tighten
   this without checking the classic maze.

4. **D2.1 was fixed conservatively to protect the training baseline.** The
   *relocate* alternative would have ADDED a 4th power pellet to every procedural
   maze (env currently drops the pacStart one → only 3 placed), changing
   `powerPelletsLeft` and the `powerBucket` observation feature — silently
   invalidating the 2-ghost track in `test_history.md`. We *dropped* the phantom
   anchor instead: `powerPelletPositions` is now honest, gameplay is byte-identical.
   **If you ever want symmetric 4-corner power pellets, that is a deliberate
   env/observation-version change, not a bugfix** — bump the obs key version and
   re-baseline.

5. **Power pellets still spawn under ghost-start tiles in `arena`/`corridors`.**
   Discovered during D2.1: those mazes' ghost starts coincide with the other three
   power-pellet corners. The env does NOT filter pellets off ghost starts (only
   pacStart), so they're placed and remain until Pac eats them — functionally
   harmless (ghosts don't consume pellets) but visually odd. Left as-is to avoid
   a gameplay/baseline change. Logged here, not fixed.

6. **`findOpenNear` can still return a wall tile only if the grid has zero open
   tiles** (truly degenerate). `validateMaze` would flag it. All real callers are
   safe now.

7. **D1.4 (collision test expansion) is deferred to Section 4 (env).** It's an
   env-behavior test that happens to live in `engine/collision.test.ts`. Do it
   alongside the environment audit so the assertions match real `step()` behavior.

8. **D1.5 (nominal `Action` type) is cross-section.** It touches env/rl/UI action
   plumbing. Don't attempt it as a Section-1-local change; schedule it as its own
   pass once the per-section audits are done.

9. **Finding-ID scheme:** this audit uses `D<section>.<n>`. The prior reviews used
   `C/H/M/L` (see `CODE_REVIEW_2026-05-17.md`) and `N1–N21` (commit messages only).
   When you fix something, keep the ID in the commit message and test comment so
   the chain stays greppable.
